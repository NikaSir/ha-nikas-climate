# UI 1.4.18 / интеграция 0.1.46

Исправления после проверки панели по БЗ NikaS 2.2:

- Масштаб применяется к уже скомпонованной рабочей области через `transform`, поэтому карточки сохраняют исходную ширину и текст больше не складывается по одной букве.
- Диапазон жеста — 75–200%. Масштаб и смещение сохраняются отдельно для каждой пары «кондиционер / вкладка».
- При увеличении рабочая область перемещается по двум осям, а Header, селектор кондиционеров и нижнее меню остаются неподвижны.
- Завершение жеста в диапазоне 97–103% фиксирует ровно 100%. Двойное касание двумя пальцами дополнительно обнуляет X/Y и обе прокрутки и кратко показывает «Масштаб 100%».
- Для ширины рабочей области заданы поля БЗ: 12 px на телефоне, 16 px на планшете и 24 px на широком экране.
- Обычный `hass`-update сохраняет корневые узлы текущей вкладки и кнопок выбора устройства, восстанавливает фокус и положение просмотра. Перестройка разрешена при смене вкладки или устройства.
- «Обновить» выполняет только read-only запрос `homeassistant.update_entity`; штатное обновление больше не перезапускает config entry.
- Вращение длится не менее 900 мс. Зелёная галочка появляется на 1400 мс только после успешного завершения обязательного запроса; ошибка показывает красный знак и видимое сообщение. Старый таймер результата не может стереть состояние нового запроса.
- Успешная галочка подтверждает принятие запроса Home Assistant и не выдаётся за подтверждение свежих данных самим кондиционером.

Проверка включает Node-тесты поведения, Chromium на контрольных размерах 320×568, 360×800, 390×844, 430×932, 768×1024, 1024×768 и 1440×900, геометрию при 100/150/200%, полный сброс, сохранение DOM-узлов и успешный/ошибочный сценарии обновления.
